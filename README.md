# 小狐狸 see me — Foxy 键盘布局可视化编辑器

> **在线使用：<https://sandyyur.github.io/foxy-see-me/>**
> 也可以直接双击本目录的 `index.html` 离线打开，无需安装、无需联网。

给 **小狐狸 Foxy 输入法** 用的可视化布局编辑器。你在网页上摆按键、设手势、调颜色，
它实时预览并导出 Foxy 能直接读的 JSON（`foxy.keyboard-layout` 格式）。
交互仿照 [f5a-see-me](https://github.com/SandyYuR/f5a-see-me)。

## 快速上手

1. 打开 `index.html`（或访问在线地址）。
2. 顶部「加载示例」选一个布局作为起点，或直接在预览区点按键开始改。
3. 改完点「导出 JSON」，把文件放进手机：

   ```
   <外部存储>/foxy/frontend/layouts/<你的文件名>.json
   ```

   精确位置是 `Android/data/com.fxliang.foxy/files/foxy/frontend/layouts/`
   （`<外部存储>` 是 Foxy 在文件管理器里暴露的入口，两者指同一个目录）。

4. 在 Foxy 设置里选择这个布局即可。文件名要放在 `frontend/layouts` 目录下，
   直接用 `.json` 结尾（不带子目录）。

> 各类文件的存放目录（与 App 端一致）：
> 布局 `frontend/layouts/`、弹出菜单 `frontend/popups/`、共享定义 `frontend/definitions.json`、
> 主题 `frontend/themes/`、符号 `frontend/symbols/`、emoji `frontend/emoji/`、
> 颜文字 `frontend/kaomoji/`。

所有改动会实时预览并自动存到浏览器本地，关掉页面下次打开还在。

## 主要功能

**实时预览**
点预览区里的任何按键就能编辑。支持 Shift / 组字 / ASCII / 停用 / 分体 / **横屏** 六种状态模拟。
按键上的角标含义（预览下方有图例）：右上蓝=长按提示、右上橙=按住提示、
底部 ⌄ =长按弹出菜单、四角小字=滑动提示、红框=引用出错、黄框=当前选中。

**分体 vs 横屏（两个不同的预览模式）**

| | 容器宽度 | 渲染哪个片段 | 区段编辑器 |
|---|---|---|---|
| **分体** | 宽屏（1228px） | 布局里的 `split` **分体片段** | 切到分体片段 |
| **横屏** | 宽屏（1228px） | **仍是常规布局** | 仍是常规布局 |

- **分体**：预览和编辑都作用于 `split` 片段（没有该片段时会提示先生成）。
- **横屏**：只是把容器加宽到分体宽度、按键按比例拉宽，**看的是同一套常规布局在宽屏下的观感**，
  不需要先造一份分体片段。预览下方会明确写出「仍渲染常规布局，未切 split 片段」。
- 两者**互斥**：勾一个会自动取消另一个（同时开会让"渲染哪个片段"产生歧义）。

**预览工具栏的两行**
- **第一行**：键盘状态开关（Shift / 组字 / ASCII / 停用 / 分体 / 横屏 / 状态标签）——
  这些是"模拟手机上的键盘状态"。切到「符号面板」页时整行隐藏。
- **第二行**：高度滑杆 + 三个**数字输入框**（按键圆角 / 按键水平间隙 / 按键垂直间隙，
  带上下箭头、单位 dp），加上 **按键边框 / 按键描边 / 滑动提示（及上滑、下滑、侧滑）**
  六个开关，再加**深浅键盘**下拉 —— 这些是"改预览怎么画"的旋钮。切到符号面板页时
  **保留**（符号面板的大小与底色也跟它们走）。

  > 按键外观三项用数字框而非滑杆：它们的可选范围很窄（0–24 / 0–16），
  > 滑杆却固定占一长条横向空间，换成数字框后这一行才腾得出位置给六个开关，
  > 也便于精确输入。超范围的值会被夹回区间并回显（敲 99 → 变 24），
  > 清空则回落默认值。
  >
  > 这六个开关对应 Foxy「设置 → 主题效果」里的同名全局设置（含 `key_border_enabled`、
  > `key_stroke_enabled`、`show_swipe_hints` 及三个方向）。
  > 它们是 **App 设置、不是主题文件内容**，所以放在这里而不是主题页 ——
  > 主题 JSON 里没有这些字段，写进去 App 也不认识。
  > 「滑动提示」是**总开关**：关掉后所有方向的提示都不显示，下面三个方向开关会置灰
  > （但保留你的勾选，重新打开总开关即恢复）。
  > 「按键描边」在**未勾选「按键边框」时不可选** —— 描边只在两者同时开启时才画，
  > 边框关着时它没有任何可见效果。

**深浅键盘与主题槽位是联动的**
预览工具栏的「键盘」下拉（深色 / 浅色）与「主题」页的槽位下拉**是同一个状态**，
改任意一边另一边会跟着变 —— 它们本来就都是"主题文件里取哪一套配色"。
（区分一下：顶栏右侧的三图标是**网页界面**的明暗，与键盘配色无关。）

**摆按键（拖动排序）**
行区段里按住按键就能拖动排序，可跨行移动；网格区段里可以把按键拖到空格换位、
拖到另一个键上交换位置。**鼠标和手机触屏都能拖**（按住挪一下才算拖动，轻点则是打开编辑）。

**按键编辑（弹窗）**
- 引用选择器：搜索你自己的按键定义，以及内置的 `rime.*` / `foxy.*`（按字母、标点、
  导航、功能、小键盘等分组）。
- 外观：标签、Shift 标签、图标、字号、宽高、按键类型、状态标签等，留空表示"继承"。
- 手势：点击、双击、四向滑动、长按（可重复、可绑弹出菜单）、按住（开始/结束动作）。
- 动作：按键码、修饰键、上屏文本、切换布局、Foxy 应用命令，一应俱全。
- 状态变体：按组字 / ASCII / 停用状态切换按键的样子和行为。
- 颜色：文字、背景、边框、按下、阴影、提示等，点色块直接取色，支持透明度。
  **每一行都会显示「当前生效的颜色 + 它来自哪一级」**——因为 Foxy 的按键颜色是
  四级继承的，留空不代表"没颜色"，而是回落到主题的某一级（见下）。

**按键颜色是怎么来的（四级继承）**
Foxy 里一个按键的颜色由高到低四级决定：

```
① 布局按键的运行时状态色（按下 / 修饰键激活 / 锁定）
② 布局按键自己的 colors
③ 主题的 keyTypes[键类型]（LETTER / FUNCTION / ACTION）
④ 主题的全局 26 色
```

注意 **② 高于 ③**：按键自己的设置会盖过主题的键类型配色（这一点与直觉相反）。
所以按键编辑对话框里，每一行颜色都会写明：

- 有本键自己的值时 →「#FF888888 ← 布局按键 colors（本键自己的设置）」；
- 留空时 → 直接告诉你**清空后会继承到哪一级、那个颜色是什么**
  （例如「← 主题 keyTypes · keyTypes.FUNCTION.background（来自主题，改主题即同步）」）；
- 来源是主题时，给一个按钮直接跳到「主题」页去改那个颜色。

> 说明：Foxy 的布局格式**不支持**「颜色引用主题字段」这种写法，
> 布局里的颜色必须是 `#RRGGBB` / `#AARRGGBB` 字面值。
> 所以"全链路对应"是在**编辑器界面**上体现的：值照旧是字面值，
> 但界面始终告诉你这个值实际来自哪一级、改哪里能改到它。

**手机竖屏优化**
屏幕 ≤640px 时自动换用更大的触摸目标、单列排版、占满宽度的预览和接近全屏的弹窗，
方便在手机上直接编辑。PC 和平板横屏界面不受影响。

**弹出菜单（长按候选）**
独立的弹出菜单文件（`foxy.popup-profile`），由按键的长按 `popupKey` 关联。
可以按键管理常规 / Shift 两组候选、气泡预览真实效果、自动补齐布局用到但还没定义的键。

键列表与按键定义 / 动作宏两页**同款交互**：

- **默认折叠**：每个 popupKey 收成一行摘要（键名 + 「布局使用 N 处」），点一下才展开候选编辑，
  键多时能一眼扫过去、快速找到要改的那个。**新建的键会自动展开**，建完就能接着配。
- **搜索**：输入框 + 「搜索」按钮，搜的是 **popupKey + 候选内容**，
  所以搜 `q` 能筛出键名、搜 `ā` 能筛出把 `ā` 当候选的那个键。
- **「使用 N」按钮**：点开列出**哪些布局的哪些按键**长按会弹出这个键，
  每条都能点击——落到布局按键上的会切到布局编辑页并选中该键，
  落到按键定义上的会切到按键定义页并选中那条定义。跳过去后高亮一直亮着，
  直到你下次点击或按键。

**分体键盘**
每个布局可以带一份 `split` 分体排布，也能"从常规布局一键生成"（自动在中间插占位）。

**导入整个布局包（多文件）**
Foxy 的布局包常常是**跨文件**的：共享定义放在 `frontend/definitions.json`，布局文件里
只写自己特有的几个键，其余靠引用共享定义。这种包只读单个文件会报一大堆
「引用无法解析」——其实文件没问题，只是缺了合并。

仍然是**同一个「导入 JSON」按钮**，按你选的东西自动判断：

- **选中 `definitions.json`** → 编辑器知道它自己不是布局，会弹出**黄色高亮的提示**，
  告诉你还需再选一次布局包所在的文件夹；点那个高亮的「选择文件夹…」按钮，
  就会把同文件夹里的 `layouts/*.json`、`popups/*.json` 一起认出来并合并；
- **一次多选几个文件**（布局 + `definitions.json`，或再加弹出菜单）→ 直接当作一个包合并
  （**最省事，推荐**）；
- **只选了一个布局文件** → 照常导入；如果它还有引用解析不了，会同样给出黄色高亮提示，
  点「选择文件夹…」补全即可；
- **选中弹出菜单文件** → 自动跳到「弹出菜单」页编辑。

识别到一个包之后，编辑器会自动：

- 把 `definitions.json` 的共享 `keys` / `actions` / `macros` 合并进布局；
- 按布局里实际用到的 `popupKey` **自动关联**对应的弹出菜单文件；
- 在文件操作区列出包内所有布局，可一键切换编辑；
- 导出时把**没改动过**的共享定义还原回 `definitions.json`（另有「导出 definitions」按钮），
  改过的部分保留在布局文件里，避免引用断掉。

> 例：工作区的 `布局/简易/` 就是这种包（自带 8 个键、引用外部 185 个键 + 34 个宏）。
> 单文件导入报 1.6 万条错误，识别整包后校验 0 错误。
>
> 说明：浏览器出于安全只把「你选中的文件」交给网页，不会透露它所在的目录，
> 所以「只选一个文件就自动读同目录」在网页里做不到——选中 `definitions.json` 后
> 补选一次文件夹，是同一入口下最接近你预期的做法。

**动作与宏（图形化编辑）**
「动作与宏」页不再是一个 JSON 文本框，而是完整的控件编辑：

- **默认折叠**：动作和宏都收成一行摘要（名字 + 效果预览），点一下才展开配置，
  条目多的时候能一眼扫过去、快速找到要改的那个。**新建的条目会自动展开**，建完就能接着配。
- **动作（actions）**：类型下拉框选「按键 / 修饰 / 文本 / 上屏 / 切布局 / 应用命令 / 引用动作名」，
  下面就是该类型专属的控件（键名下拉、修饰键勾选框、命令下拉…），改完即时写回。
- **宏（macros）**：每个步骤占一行，行内直接是动作编辑器 —— **一步就是一个动作**，
  可以用下拉框引用已有动作名，也可以内联一个动作。每行有 ▲▼ 调序、＋插入、✕删除，
  还可以按住左侧把手拖动排序。
- **按键下拉带中文备注**：低层键码后面括号注明它是什么键，例如
  `ESCAPE（Esc 退出）`、`BACKSPACE（退格）`、`KP_5（小键盘 5）`、`F1（功能键 F1）`，
  不用再去猜英文码的含义。备注只影响显示，写进文件的仍是标准键码。
- 两边都保留「编辑原始 JSON…」入口，处理控件覆盖不到的写法（例如宏里嵌套宏），
  这类写法会原样保留并标注原因，不会被静默改写。

**「使用数」——查引用、一键跳过去**
按键定义页和「动作与宏」页的每个条目都带一个「使用 N」按钮，点开是网页内建弹窗，
列出它被哪些布局、哪些地方用到：

- **点击条目直接跳转**：会切到那个布局、选中对应的按键并滚动过去（分体片段也会自动切过去）；
  引用发生在弹出菜单里的，则跳到「弹出菜单」页并选中该键；
  引用发生在**按键定义 / 动作 / 宏**内部的，会切到对应的列表页、展开并选中那条定义
  （这类引用没有布局坐标，但同样可点，不会变成点不动的死行）。
- **跳过去之后高亮会一直亮着**，直到你下次点击或按键才消失 —— 不必抢在它闪完之前找到目标。
  落到**列表条目**上时是蓝色脉冲边框；落到**布局里的按键**上时是**黄色**光晕
  （与它自带的黄色选中框同色系，不刺眼），点一下光晕消失，按键保持正常的选中黄框。
- **能穿透多层引用**：布局 → 宏 → 动作 → 动作 这种链子也会追到底，
  并注明「经由 宏 m1」，所以不会出现「明明在用却显示 0 处」。
- **反向也看得到：它自己引用了谁**。弹窗下半部分是「引用（它用到的动作与宏）」，
  列出这条定义用到的动作名 / 宏名，并标出出现位置（例如 `tap`、`swipe.up`、`步骤1`）。
  点击同样能跳到「动作与宏」页并选中该条目 —— 以前这些引用只能在原始 JSON 里翻。
  若引用的目标已被删掉，会直接标「不存在」并且不给跳转按钮，避免点了没反应。
  > **动作条目没有这一节**：动作是最基础的条目，它只被引用、不会引用别人，
  > 所以动作的弹窗只列「被谁引用」，不会多出一句"它没有引用任何条目"的空话。
  > 有「引用」一节的是按键定义与宏。
- 没有引用的条目会明确告诉你它没被用到，删除前心里有数。
- 按键定义页**整行都能点**，点一下直接进编辑，不用对准小按钮（行内只剩「使用」和「删除」）。

**搜索与新建（多张列表同构）**
按键定义 / 动作 / 宏 / 弹出菜单键 / **符号面板分组** 各张列表顶部都是同一套工具条
（按键定义、动作、宏、符号分组另有「新建」一组）：

> 「列表」与「页签」不是一回事：这些列表落在**五个页签**里 ——
> 按键定义 1 张、**动作与宏 2 张**（动作 + 宏）、弹出菜单 1 张、符号面板 1 张；
> 顶部共 6 个页签，多出的「布局编辑」不是列表页、没有搜索框，
> 「主题」页是颜色网格而非列表。

- **搜索**：输入框 + 「搜索」按钮。边打字边筛，也可以点按钮或按回车确认；
  搜的是**名称 + 内容**，所以搜 `CTRL` 能筛出带 Ctrl 的动作、搜 `HOME` 能筛出用 Home 的宏、
  搜 `ā` 能筛出把它当候选的弹出菜单键。
  筛过之后上方会显示「匹配 3 / 12 项」，清空即恢复全部。
- **✕ 清空**：搜索框右内侧有个叉号，点一下清空已输入的文字（空框时它不出现，不碍事），
  清空后焦点留在框里，可以直接接着重新输入。四个列表都有。
- **新建**（前三张列表）：输入框 + 「+ 新建…」按钮（不用再弹输入框问了）。建好后**自动滚到新条目并高亮**，
  高亮会一直亮着，直到你下次点击或按键才消失，一眼就能看到刚建的东西；输入框清空，
  要配置就点它（按键定义页点整行、动作/宏点摘要行展开，
  新建的条目已默认展开）。（按键定义 / 动作 / 宏）三张列表行为一致，**都不会**替你弹出编辑对话框。
  > 新条目始终追加在列表末尾 —— 这是刻意的：JSON 的键顺序保持插入序，
  > 不去重排喂给 Foxy 的布局文件，只把视口挪过去。
- 手机竖屏下**搜索一行、新建一行**，每组里的输入框和按钮仍在同一行；
  桌面则是两行并排。

**主题（键盘配色）**
独立的主题文件（`foxy.keyboard-theme`）编辑页，改颜色**实时反映到键盘预览**。

- **两套槽位**：主题里 `light` / `dark` 是**两个独立的配色槽位**
  （Foxy 端由「跟随系统深浅色」决定用哪个，可手动指定），
  与预览工具栏的「键盘」下拉**是同一个状态**（改一边另一边跟着变），
  但**不会**写进主题文件本身。
  > 区分一下：顶栏右侧的三图标管的是**这个网页界面**的明暗，与键盘配色无关。
- **字段面按 Foxy 实际读取的范围**：26 个全局颜色 + `keyTypes` 的
  `LETTER` / `FUNCTION` / `ACTION` **三类**，每类 **10** 个字段
  （文字/背景/按下/边框/阴影/四个方向提示/提示）。
  留空表示「回落 / 继承」，例如四个方向提示色留空就继承 `keyHintTextColor`。
- **颜色优先级**（预览与手机一致，由高到低）：
  按键状态色 → 布局里该键自己的 `colors` → 主题的 `keyTypes[键类型]` → 主题全局 26 色。
  注意**布局里每个按键的 `colors` 会盖过主题的 keyTypes**。
- **两个按键开关的组合**（App「设置 → 主题效果」的全局开关，不写进主题文件；
  在**预览工具栏第二行**上，不在主题页）：
  - 「按键边框」开启 → 键盘底色用 `altKeyboardColor`；关闭 → 回落 `keyboardColor`。
  - 「按键描边」是**另一个**开关（默认关）。只有**边框与描边同时开启**时，
  键上才会出现 `keyBorderColor` 那条 1px 边框 —— 这正是手机默认状态
  （边框开、描边关）下**看不到** `keyBorderColor` 的原因，
  别以为是编辑器没生效。
  - 「按键边框」关闭时，键面是**纯色圆角块** —— 既没有 `keyBorderColor` 边框，
  **也没有阴影层**。所以关掉它之后键看起来更"平"，那是对的。
- 「以内置默认色新建主题」用 Foxy 内置的默认配色作初值，预览外观与手机开箱状态对齐。
- 导出文件名跟随主题的 `name` 字段（App 端就是这么定位文件的）。
  名字里含 `/` `:` 等字符时，编辑器会按 App 的规则做百分号转义（4 位十六进制、**小写**），
  并在输入框旁把最终文件名显示出来。
- ⭐ **没导入主题时，预览也按「App 内置默认主题」上色**（深/浅两套各自生效）——
  也就是手机开箱、用户还没自定义配色时的样子。所以预览不再有"完全不上色、
  走网页预置色"那种状态：预览看到的就是手机上会看到的。
  「以内置默认色新建主题」拿到的初值与此**完全一致**。

**符号面板（符号 / emoji / 颜文字）**
三类符号目录（`{multiLine, groups}` 格式，**没有 `type` 字段**）的编辑页，
顶部下拉切换三类，各占一份独立数据。

**切到这一页时，上方的预览区会换成「符号面板预览」** —— 因为 App 里符号面板
不是弹在键盘上的浮层，而是一块**整块替换键盘区域**的面板，所以这里也按那个样子预览：

- **尺寸与布局预览完全一致**（高度按同一套布局高度换算），这样你切换两页时预览盒子
  不会跳大小 —— 看符号面板想判断的正是"它在真机那块屏会不会挤"。
- **左列**是分组列表（可滚动）+ 底部 `⌨` / `⌫` 两个热键；**右列**是符号格
  （6 格一行，或 `multiLine` 时 1 格一行）。
- **分组和符号区各自滚动**，条目再多也不会把预览面板拉长 —— 与实机一致（两列各是一个滚动区）。
  滚动条已**隐藏**（手机上的滚动指示是 Android 那套细条、会自动淡出，不是网页粗白条），
  但**滚动能力保留**：鼠标滚轮、触控板、手指滑动都照常可用。
- **切到这一页时，那排调整键盘几何的控件会隐藏**（高度滑杆与三个外观数字框）——
  它们改的是键盘几何，对符号面板不起作用，摆在这里是噪音。
  **深浅配色下拉会保留**：面板底色也跟它走。
- 点左侧分组可切换查看。面板底色、格子色、分组选中色都跟随主题。
- 说明文字放在**预览键盘区之外**（面板下方的状态行），不占用"手机的样貌"。

- **分组折叠 + 搜索**：每个分组收成一行摘要（组名 + 条目数），点开才编辑；
  搜索同时匹配**组名的三种语言**与**条目内容**。
- **载入示例**：下拉里给的是**真实示例文件**（符号 35 组 / 表情 58 组 / 颜文字 15 组，
  随编辑器一起分发），选一类点「载入示例」就能拿到一份完整可用的符号表当起点。
- **`multiLine` 开关**：开启时预览每行 1 个、高度自适应；关闭时每行 6 个。
  **注意**：关闭状态下格高固定，长条目在手机上会被**等比缩小**到很小、可读性差
  （不是被裁掉，条目仍完整可见）—— 所以颜文字这类多字符内容应保持开启，
  编辑器会在检测到多字符条目时给出提示。
- **组名三语**：`zh` / `zh-Hant` / `en` 三栏。至少填 `zh`；
  `zh-Hant` 供繁体与「无中文匹配」两种情况回退使用。
- **空组会被 Foxy 静默丢弃**：组名为空或条目为空的分组，App 端会整组忽略，
  编辑器会对这种写法给出提示。
- **导入兼容旧格式**：顶层直接是数组的老文件也能读入（此时按 `multiLine: false` 处理）。
- 目录是 `frontend/symbols`、`frontend/emoji`、`frontend/kaomoji`（**不能混放**）。

> ⚠️ 与布局**相反**：符号的**内置数据来自 App 安装包**，
> 你放进上述目录的文件要在「设置 → 符号布局」里**被选中**才生效 ——
> 放一份同名文件**不会**自动覆盖内置。编辑器在文件卡里也写了这条提示。
>
> 另：`symbols` / `emoji` / `kaomoji` 这三个名字被 App 用于识别符号面板，
> 所以**不能**再拿它们当自定义布局名（当 `switch_layout` 目标时会被识别成面板）。

**其它**
按键定义 / 动作 / 宏的管理，导入导出，撤销重做（Ctrl+Z / Ctrl+Y），内置多个示例布局。
顶栏右侧常驻撤销 / 重做按钮，随时可用；标题与右侧的 GitHub 链接都指向本仓库。

**浮动工具（不用滑回顶部）**
页面滚过顶栏后，右上角会浮出**撤销 / 重做**、右下角浮出**回到顶部**，
编辑长列表时随手就能点，不必每次都滑回页首。

- 为什么滚下去才出现：顶栏右侧本来就有同款撤销/重做按钮，固定定位常驻会和它们叠在一起；
  滚过顶栏后顶栏已看不到，这时浮出来才真正派上用场，也不重叠。
- 两处撤销/重做（浮动 / 顶栏）状态始终同步。

## 校验

编辑器实时执行与 Foxy 一致的校验（结果在预览下方）：

- 每个 `ref` 引用都能解析（含循环检测、变体 / 手势 / 动作 / 宏引用）；
- 每个按键解析后都有点击动作；`hold` 和 `longPress` 不能同时设；
- `weight: "auto"` 的行要有足够的 `totalWeight`；网格不越界、不重叠（空格子只提示不报错）；
- 布局变体目标存在且无循环；各布局总高度一致性（警告）；
- `split` 分体片段独立校验；`text_editor` 必须恰好一个 rows 区段、一行。

**点一下就跳到出错处**：展开「校验详情」，带位置信息的条目都可以点击，
编辑器会自动切到对应布局 / 分体片段、选中那个按键并滚动到它；
问题出在**按键定义 / 动作 / 宏**里的（这些位置没有布局坐标），
会切到对应列表页并选中那条定义。
从校验跳过去的高亮是**红色**（提示"这里有错"），会一直亮到你下次点击或按键；
布局里的按键同样是红框盖在选中框上，点击后回到正常的黄色选中态，
不用自己在一堆报错里猜是哪一处。

## JSON 语法自动修复

手改布局文件最常见的坑是**多余的尾逗号**，严格 JSON 会直接报错读不进来。
本编辑器会主动发现并修复这类问题：

- 编辑「布局 JSON」时自动体检，列出问题类型、次数和行号。
- 一键修复：可以「修好并应用」，也可以「只修文本、先看再应用」。
- 能修的类型：尾逗号、BOM、注释、单引号、没加引号的键名、全角标点。
- 修完仍无法解析时会如实报错，不会给假的"已修复"。
- 导入文件时若只有这类小问题会自动修好并导入，并说明修了哪几处。

> 编辑器导出的 JSON 永远是规范的，所以"宽松导入"只影响能不能把手改的文件读进来，
> 不会污染 Foxy 端。透明性靠**明确告知修了什么**来保证，而不是靠拒绝读取。

## 在电脑上测竖屏

最省事的办法是 **DevTools 设备模式**（F12 → Ctrl+Shift+M，选个手机机型）。日常改样式看效果够用。

但它有盲区：那是「把窗口变窄 + 假装是触屏」，**不是真移动端语义**。有一类 bug 只在
真正的移动模式下出现，缩窗口永远抓不到。举个本项目实际踩到的例子——加载
`cc_grid_4.json`（48 列大网格）在 414px 宽下：

| 模式 | `window.innerWidth` | 水平溢出 | 浮动按钮 |
|---|---|---|---|
| 桌面（只缩窗口） | 414 ✓ | 0 ✓ | 正常 ✓ |
| 移动端语义 | **1656** ✗ | **1507px** ✗ | **不出现** ✗ |

同一个宽度、同一份 CSS，结果完全相反。原因是移动模式下页面被横向撑开会触发视口缩放，
纵向反而滚不动，`updateFloatTools()` 永远读到 `scrollTop=0`，三个浮动按钮就再也不显示。

所以需要一个**跑真移动端语义**的检查脚本：

```
npm i -D playwright-core      # 只需装一次，用本机已装的 Edge/Chrome，不额外下载浏览器

node tools/mobile-preview.js                 # 默认布局，跑 5 个典型竖屏
node tools/mobile-preview.js cc_grid_4.json  # 指定某个内置示例
node tools/mobile-preview.js --all           # 所有内置示例都过一遍
```

它会检查：水平溢出（含逐标签页）、浮动按钮滚后是否出现、宽网格末格能否横向滚到、
JS 错误；截图落在 `.mobile-preview/`（该目录不必入库）。**退出码非 0 表示发现问题**，
可以直接接进 CI。

它比「缩窗口」多做的三件事：

1. **`isMobile` + `hasTouch` + 真实触摸事件** —— 走 CDP `Input.dispatchTouchEvent`，
   是真正的手指滑动，不是 mouse wheel 模拟；`pointerType` 也才是 `touch`。
2. **逐标签页检查** —— 布局编辑 / 按键定义 / 动作与宏 / 弹出菜单 / 主题 / 符号面板
   六页各查一遍，因为各 panel 的 DOM 差异大，一处溢出未必牵连其他页。
3. **浮动按钮可达性** —— 用真实上滑滚过阈值，确认三个浮动按钮真的出现（上表那个 bug
   就卡在这里）。

> 想指定浏览器：`MOBILE_PREVIEW_BROWSER="C:\路径\msedge.exe"`。
> 待测视口列表在脚本顶部的 `VIEWPORTS` 里，改那里就行。

**DevTools 和这个脚本都测不到、只能上真机的**：软键盘弹起导致的 `visualViewport` 收缩、
地址栏收放对 `100vh` 的影响、真实触摸的延迟与惯性滚动、长按系统菜单。

## 说明

- 保存放置时会把 `override` 里的字段扁平化为直接字段（优先级：定义链 < override < 直接字段）。
- `null` 语义与 Foxy 一致：清空标签、恢复默认权重、清除颜色等；`tap: null` 例外——保留继承的点击动作。
- 每个按键的 `colors` 覆盖属于布局数据，已支持。
- **主题文件**（`foxy.keyboard-theme`，独立文件）可在「主题」页编辑，改色实时反映到键盘预览；
  但 Foxy 的**全局主题设置**（主题列表选择、跟随系统等）仍属 App 端，不在本工具范围。
- 主题颜色与布局颜色的**优先级**（由高到低）：布局按键状态色 → 布局每键 `colors` →
  主题 `keyTypes[键类型]` → 主题全局颜色。注意**布局每键覆盖高于主题 keyTypes**。
- 弹出菜单和布局是两份独立文件，各自导入导出（布局进 `frontend/layouts/`，弹出菜单进 `frontend/popups/`）。
  如果它们和一个 `definitions.json` 放在同一个文件夹里，用「导入 JSON」选中 `definitions.json`
（或一次多选几个文件）即可一次读全，会自动合并与关联。
- **符号 / emoji / 颜文字**（`frontend/symbols`、`frontend/emoji`、`frontend/kaomoji`）在「符号面板」页编辑。
  注意其读取机制与布局**相反**：内置数据走 APK `assets/`，外部文件需在
  「设置 → 符号布局」里**被选中**才生效——放同名文件不会自动覆盖内置。
- 把 `symbols` / `emoji` / `kaomoji` 当 `switch_layout` 目标时会被识别为**符号面板**，
  所以这三个名字不能用作自定义布局名。

格式完整参考见 [`skills/`](skills/)：
`skills/SKILL.md`（面向 AI 的完整格式规范与编辑要点，含 Quick Start / 校验清单 / 常见错误对照表），
以及三个 JSON Schema —— `skills/foxy-keyboard-layout.schema.json`、
`skills/foxy-popup-profile.schema.json`、`skills/foxy-definitions.schema.json`。
