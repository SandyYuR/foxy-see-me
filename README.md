# 小狐狸 see me — Foxy 键盘布局可视化编辑器

> **在线使用：<https://sandyyur.github.io/foxy-see-me/>**
> 也可以直接双击本目录的 `index.html` 离线打开，无需安装、无需联网。

给 **小狐狸 Foxy 输入法** 用的可视化布局编辑器。你在网页上摆按键、设手势、调颜色，
它实时预览并导出 Foxy 能直接读的 JSON（`foxy.keyboard-layout` 格式）。
交互仿照 [f5a-see-me](https://github.com/SandyYuR/f5a-see-me)。

## 快速上手

1. 打开 `index.html`（或访问在线地址）。
2. 顶部「加载示例」选一个布局作为起点，或直接在预览区点按键开始改。
3. 改完点「导出 JSON」，把文件放进手机：

   ```
   <外部存储>/foxy/frontend/layouts/<你的文件名>.json
   ```

4. 在 Foxy 设置里选择这个布局即可。文件名要放在 `frontend/layouts` 目录下，
   直接用 `.json` 结尾（不带子目录）。

所有改动会实时预览并自动存到浏览器本地，关掉页面下次打开还在。

## 主要功能

**实时预览**
点预览区里的任何按键就能编辑。支持 Shift / 组字 / ASCII / 停用 / 分体五种状态模拟，
深浅两套配色。按键上的角标含义（预览下方有图例）：右上蓝=长按提示、右上橙=按住提示、
底部 ⌄ =长按弹出菜单、四角小字=滑动提示、红框=引用出错、黄框=当前选中。

**摆按键（拖动排序）**
行区段里按住按键就能拖动排序，可跨行移动；网格区段里可以把按键拖到空格换位、
拖到另一个键上交换位置。**鼠标和手机触屏都能拖**（按住挪一下才算拖动，轻点则是打开编辑）。

**按键编辑（弹窗）**
- 引用选择器：搜索你自己的按键定义，以及内置的 `rime.*` / `foxy.*`（按字母、标点、
  导航、功能、小键盘等分组）。
- 外观：标签、Shift 标签、图标、字号、宽高、按键类型、状态标签等，留空表示"继承"。
- 手势：点击、双击、四向滑动、长按（可重复、可绑弹出菜单）、按住（开始/结束动作）。
- 动作：按键码、修饰键、上屏文本、切换布局、Foxy 应用命令，一应俱全。
- 状态变体：按组字 / ASCII / 停用状态切换按键的样子和行为。
- 颜色：文字、背景、边框、按下、阴影、提示等，点色块直接取色，支持透明度。

**手机竖屏优化**
屏幕 ≤640px 时自动换用更大的触摸目标、单列排版、占满宽度的预览和接近全屏的弹窗，
方便在手机上直接编辑。PC 和平板横屏界面不受影响。

**弹出菜单（长按候选）**
独立的弹出菜单文件（`foxy.popup-profile`），由按键的长按 `popupKey` 关联。
可以按键管理常规 / Shift 两组候选、气泡预览真实效果、自动补齐布局用到但还没定义的键。

**分体键盘**
每个布局可以带一份 `split` 分体排布，也能"从常规布局一键生成"（自动在中间插占位）。

**导入整个布局包（多文件）**
Foxy 的布局包常常是**跨文件**的：共享定义放在 `frontend/definitions.json`，布局文件里
只写自己特有的几个键，其余靠引用共享定义。这种包只读单个文件会报一大堆
「引用无法解析」——其实文件没问题，只是缺了合并。

仍然是**同一个「导入 JSON」按钮**，按你选的东西自动判断：

- **选中 `definitions.json`** → 编辑器知道它自己不是布局，会弹出**黄色高亮的提示**，
  告诉你还需再选一次布局包所在的文件夹；点那个高亮的「选择文件夹…」按钮，
  就会把同文件夹里的 `layouts/*.json`、`popups/*.json` 一起认出来并合并；
- **一次多选几个文件**（布局 + `definitions.json`，或再加弹出菜单）→ 直接当作一个包合并
  （**最省事，推荐**）；
- **只选了一个布局文件** → 照常导入；如果它还有引用解析不了，会同样给出黄色高亮提示，
  点「选择文件夹…」补全即可；
- **选中弹出菜单文件** → 自动跳到「弹出菜单」页编辑。

识别到一个包之后，编辑器会自动：

- 把 `definitions.json` 的共享 `keys` / `actions` / `macros` 合并进布局；
- 按布局里实际用到的 `popupKey` **自动关联**对应的弹出菜单文件；
- 在文件操作区列出包内所有布局，可一键切换编辑；
- 导出时把**没改动过**的共享定义还原回 `definitions.json`（另有「导出 definitions」按钮），
  改过的部分保留在布局文件里，避免引用断掉。

> 例：工作区的 `布局/简易/` 就是这种包（自带 8 个键、引用外部 185 个键 + 34 个宏）。
> 单文件导入报 1.6 万条错误，识别整包后校验 0 错误。
>
> 说明：浏览器出于安全只把「你选中的文件」交给网页，不会透露它所在的目录，
> 所以「只选一个文件就自动读同目录」在网页里做不到——选中 `definitions.json` 后
> 补选一次文件夹，是同一入口下最接近你预期的做法。

**动作与宏（图形化编辑）**
「动作与宏」页不再是一个 JSON 文本框，而是完整的控件编辑：

- **默认折叠**：动作和宏都收成一行摘要（名字 + 效果预览），点一下才展开配置，
  条目多的时候能一眼扫过去、快速找到要改的那个。**新建的条目会自动展开**，建完就能接着配。
- **动作（actions）**：类型下拉框选「按键 / 修饰 / 文本 / 上屏 / 切布局 / 应用命令 / 引用动作名」，
  下面就是该类型专属的控件（键名下拉、修饰键勾选框、命令下拉…），改完即时写回。
- **宏（macros）**：每个步骤占一行，行内直接是动作编辑器 —— **一步就是一个动作**，
  可以用下拉框引用已有动作名，也可以内联一个动作。每行有 ▲▼ 调序、＋插入、✕删除，
  还可以按住左侧把手拖动排序。
- **按键下拉带中文备注**：低层键码后面括号注明它是什么键，例如
  `ESCAPE（Esc 退出）`、`BACKSPACE（退格）`、`KP_5（小键盘 5）`、`F1（功能键 F1）`，
  不用再去猜英文码的含义。备注只影响显示，写进文件的仍是标准键码。
- 两边都保留「编辑原始 JSON…」入口，处理控件覆盖不到的写法（例如宏里嵌套宏），
  这类写法会原样保留并标注原因，不会被静默改写。

**「使用数」——查引用、一键跳过去**
按键定义页和「动作与宏」页的每个条目都带一个「使用 N」按钮，点开是网页内建弹窗，
列出它被哪些布局、哪些地方用到：

- **点击条目直接跳转**：会切到那个布局、选中对应的按键并滚动过去（分体片段也会自动切过去）；
  引用发生在弹出菜单里的，则跳到「弹出菜单」页并选中该键。
- **能穿透多层引用**：布局 → 宏 → 动作 → 动作 这种链子也会追到底，
  并注明「经由 宏 m1」，所以不会出现「明明在用却显示 0 处」。
- 没有引用的条目会明确告诉你它没被用到，删除前心里有数。
- 按键定义页**整行都能点**，点一下直接进编辑，不用对准小按钮（行内只剩「使用」和「删除」）。

**搜索与新建（三个列表一致）**
按键定义 / 动作 / 宏 三页顶部都是同一套工具条，每页两行各管一件事：

- **搜索**：输入框 + 「搜索」按钮。边打字边筛，也可以点按钮或按回车确认；
  搜的是**名称 + 内容**，所以搜 `CTRL` 能筛出带 Ctrl 的动作、搜 `HOME` 能筛出用 Home 的宏。
  筛过之后上方会显示「匹配 3 / 12 项」，清空即恢复全部。
- **新建**：输入框 + 「+ 新建…」按钮（不用再弹输入框问了）。建好后**自动滚到新条目并短暂高亮**，
  一眼就能看到刚建的东西；输入框清空，要配置就点它（按键定义页点整行、动作/宏点摘要行展开，
  新建的条目已默认展开）。三页行为一致，**都不会**替你弹出编辑对话框。
  > 新条目始终追加在列表末尾 —— 这是刻意的：JSON 的键顺序保持插入序，
  > 不去重排喂给 Foxy 的布局文件，只把视口挪过去。
- 手机竖屏下**搜索一行、新建一行**，每组里的输入框和按钮仍在同一行；
  桌面则是两行并排。

**其它**
按键定义 / 动作 / 宏的管理，导入导出，撤销重做（Ctrl+Z / Ctrl+Y），内置多个示例布局。
顶栏右侧常驻撤销 / 重做按钮，随时可用；标题与右侧的 GitHub 链接都指向本仓库。

**浮动工具（不用滑回顶部）**
页面滚过顶栏后，右上角会浮出**撤销 / 重做**、右下角浮出**回到顶部**，
编辑长列表时随手就能点，不必每次都滑回页首。

- 为什么滚下去才出现：顶栏右侧本来就有同款撤销/重做按钮，固定定位常驻会和它们叠在一起；
  滚过顶栏后顶栏已看不到，这时浮出来才真正派上用场，也不重叠。
- 三处撤销/重做（浮动 / 顶栏 / 「布局与文件操作」卡片内）状态始终同步。

## 校验

编辑器实时执行与 Foxy 一致的校验（结果在预览下方）：

- 每个 `ref` 引用都能解析（含循环检测、变体 / 手势 / 动作 / 宏引用）；
- 每个按键解析后都有点击动作；`hold` 和 `longPress` 不能同时设；
- `weight: "auto"` 的行要有足够的 `totalWeight`；网格不越界、不重叠（空格子只提示不报错）；
- 布局变体目标存在且无循环；各布局总高度一致性（警告）；
- `split` 分体片段独立校验；`text_editor` 必须恰好一个 rows 区段、一行。

**点一下就跳到出错的键**：展开「校验详情」，带位置信息的条目可以点击，
编辑器会自动切到对应布局 / 分体片段、选中那个按键并滚动到它，
不用自己在一堆报错里猜是哪个键。

## JSON 语法自动修复

手改布局文件最常见的坑是**多余的尾逗号**，严格 JSON 会直接报错读不进来。
本编辑器会主动发现并修复这类问题：

- 编辑「布局 JSON」时自动体检，列出问题类型、次数和行号。
- 一键修复：可以「修好并应用」，也可以「只修文本、先看再应用」。
- 能修的类型：尾逗号、BOM、注释、单引号、没加引号的键名、全角标点。
- 修完仍无法解析时会如实报错，不会给假的"已修复"。
- 导入文件时若只有这类小问题会自动修好并导入，并说明修了哪几处。

> 编辑器导出的 JSON 永远是规范的，所以"宽松导入"只影响能不能把手改的文件读进来，
> 不会污染 Foxy 端。透明性靠**明确告知修了什么**来保证，而不是靠拒绝读取。

## 在电脑上测竖屏

最省事的办法是 **DevTools 设备模式**（F12 → Ctrl+Shift+M，选个手机机型）。日常改样式看效果够用。

但它有盲区：那是「把窗口变窄 + 假装是触屏」，**不是真移动端语义**。有一类 bug 只在
真正的移动模式下出现，缩窗口永远抓不到。举个本项目实际踩到的例子——加载
`cc_grid_4.json`（48 列大网格）在 414px 宽下：

| 模式 | `window.innerWidth` | 水平溢出 | 浮动按钮 |
|---|---|---|---|
| 桌面（只缩窗口） | 414 ✓ | 0 ✓ | 正常 ✓ |
| 移动端语义 | **1656** ✗ | **1507px** ✗ | **不出现** ✗ |

同一个宽度、同一份 CSS，结果完全相反。原因是移动模式下页面被横向撑开会触发视口缩放，
纵向反而滚不动，`updateFloatTools()` 永远读到 `scrollTop=0`，三个浮动按钮就再也不显示。

所以需要一个**跑真移动端语义**的检查脚本：

```
npm i -D playwright-core      # 只需装一次，用本机已装的 Edge/Chrome，不额外下载浏览器

node tools/mobile-preview.js                 # 默认布局，跑 5 个典型竖屏
node tools/mobile-preview.js cc_grid_4.json  # 指定某个内置示例
node tools/mobile-preview.js --all           # 所有内置示例都过一遍
```

它会检查：水平溢出（含逐标签页）、浮动按钮滚后是否出现、宽网格末格能否横向滚到、
JS 错误；截图落在 `.mobile-preview/`（该目录不必入库）。**退出码非 0 表示发现问题**，
可以直接接进 CI。

它比「缩窗口」多做的三件事：

1. **`isMobile` + `hasTouch` + 真实触摸事件** —— 走 CDP `Input.dispatchTouchEvent`，
   是真正的手指滑动，不是 mouse wheel 模拟；`pointerType` 也才是 `touch`。
2. **逐标签页检查** —— 布局编辑 / 按键定义 / 动作与宏 / 弹出菜单四页各查一遍，
   因为四个 panel 的 DOM 差异大，一处溢出未必牵连其他页。
3. **浮动按钮可达性** —— 用真实上滑滚过阈值，确认三个浮动按钮真的出现（上表那个 bug
   就卡在这里）。

> 想指定浏览器：`MOBILE_PREVIEW_BROWSER="C:\路径\msedge.exe"`。
> 待测视口列表在脚本顶部的 `VIEWPORTS` 里，改那里就行。

**DevTools 和这个脚本都测不到、只能上真机的**：软键盘弹起导致的 `visualViewport` 收缩、
地址栏收放对 `100vh` 的影响、真实触摸的延迟与惯性滚动、长按系统菜单。

## 说明

- 保存放置时会把 `override` 里的字段扁平化为直接字段（优先级：定义链 < override < 直接字段）。
- `null` 语义与 Foxy 一致：清空标签、恢复默认权重、清除颜色等；`tap: null` 例外——保留继承的点击动作。
- 主题（整体配色）不在本工具范围内；每个按键的 `colors` 覆盖属于布局数据，已支持。
- 弹出菜单和布局是两份独立文件，各自导入导出（布局进 `frontend/layouts/`，弹出菜单进 `frontend/popups/`）。
  如果它们和一个 `definitions.json` 放在同一个文件夹里，用「导入 JSON」选中 `definitions.json`
（或一次多选几个文件）即可一次读全，会自动合并与关联。

格式完整参考见 [`skills/`](skills/)：
`skills/SKILL.md`（面向 AI 的完整格式规范与编辑要点，含 Quick Start / 校验清单 / 常见错误对照表），
以及三个 JSON Schema —— `skills/foxy-keyboard-layout.schema.json`、
`skills/foxy-popup-profile.schema.json`、`skills/foxy-definitions.schema.json`。
